Writing a plugin

Everything Trunk can be extended with is a plugin: a small class registered with an entry point. Start from a base class and run the contract suite.

Everything Oaken Trunk can be extended with is a plugin: a small class registered with a Python entry point. Start from a base class, override what your plugin does, and run the contract suite. This is the same model as Oaken Mail's plugins, so the habits carry over.

1

The seven kinds, and the plain plugin

Kind Entry-point group Base class What it does
Ingestor oaken_trunk.ingestors BaseIngestor Speaks a protocol and hands core a byte stream and an envelope.
Retriever oaken_trunk.retrievers BaseRetriever Speaks a read protocol (POP3) and maps it onto list, lease, fetch and ack. Holds no store.
Store oaken_trunk.stores BaseStore Storage primitives (blobs, compare-and-set, ordered indexes). Core builds the spool, locks and counters on them.
Sender oaken_trunk.senders BaseSender Relays an outbound message to its destination.
Authenticator oaken_trunk.authenticators BaseAuthenticator Verifies a request or connection: signed requests, SMTP AUTH, mTLS. Core owns freshness, replay and the default deny.
MTA oaken_trunk.mtas BaseMTA Declares how an MTA hands over mail: env names, arguments, exit codes. The base supplies steamer NAME submit.
Listener oaken_trunk.listeners BaseListener Watches the envelope, headers, end and stored events. Sees headers and digests only, annotates, never removes a core protection.

Every base class extends BasePlugin, which gives the context, lifecycle, health, @command and ctx.ops (the operations the plugin declared in calls). A plugin that fits no kind, such as an autoscaler, extends BasePlugin directly and registers in oaken_trunk.plugins. It has no kind-specific role, so its only power is the commands it exposes and the operations it declared.

Import them from oaken_trunk.plugins.base, or from oaken_trunk.plugins, which re-exports them.

First-party plugins (oaken_trunk_*) register exactly as a third party's would. The exact signatures are on the generated plugin contracts page.

2

What every base class gives you

  • self.ctx: your settings (the [ingest.<name>], [store.<name>] or [sender.<name>] table of config.toml), a logger, the clock, the worker's thread pool, and the global limits. Secrets come from the environment or files, never from config.
  • start() and stop() lifecycle hooks, called by the host, with health reported to doctor.
  • Capabilities inferred from what you wrote, so there is no second list to keep in step.
  • Lenient return types: a dict, tuple or plain value is coerced to the strict contract type, and a mistake produces a readable message such as spool 'mine': lease() returned 3 ids for limit 2.
  • Isolation: an error fails that one message or operation and is logged. It never stops core.
3

Commands

Mark a method with @command and it becomes the operation plugin.verb, with typed input and output, a permission (read or mutate) and an mcp setting (off or never). The CLI, HTTP API, web UI and MCP all take it from the registry. An unmarked method is unreachable, and a plugin cannot take a core name. The decorator limits what a plugin exposes, not what its code can do.

Plugins run in-process and are not sandboxed in v1. Core never imports a plugin, and a plugin never touches core's counters or another plugin's storage; it returns data and receives streams.

4

Memory rule for plugin authors

Never read a whole message into memory. Bodies arrive and leave as async iterators of bounded chunks. A plugin that buffers a message breaks the gateway's memory guarantee and fails the contract suite's streaming test.

5

A store in one screen

A store is storage primitives. Core builds the spool (fan-out per device, lease, ack, nack, renew, body cleanup), locks, counters and the caps on top of them, so a store never implements queue logic (ADR 0014).

from oaken_trunk.plugins.base import BaseStore

class MyStore(BaseStore):
    version = "0.1"

    async def blob_put(self, key, chunks):      # an async iterator of bounded chunks; durable on return
        async for chunk in chunks:
            await self.backend.append(key, chunk)

    def blob_open(self, key):                    # an async iterator of chunks
        return self.backend.read(key)

    async def blob_drop(self, key):              # idempotent
        await self.backend.delete(key)

    async def cas(self, key, expect, new, ttl=None):   # atomic; True if it swapped
        return await self.backend.compare_and_set(key, expect, new, ttl)

    async def index_add(self, name, member, score): ...
    async def index_remove(self, name, member): ...
    async def index_range(self, name, lo, hi, limit): ...
You write You gain
the blob, cas and index primitives A working store for any role: bodies, queues, coordination
watch(name) Event-driven wake-up; without it the host polls
commit, lease, ack, nack or renew A faster path for that operation, if it passes the same spool suite

[store] bodies, queues and coordination each name a store, so a hybrid (bodies in S3, queues and locks in Redis) is configuration.

6

A protocol plugin in one screen

Ingestors and retrievers extend BaseLineServer (through BaseIngestor or BaseRetriever). The base owns TLS, line and time limits, connection caps, dot-stuffing, login through the authenticators, and the fuzz harness. A plugin declares its command table.

from oaken_trunk.plugins.base import BaseRetriever, cmd

class Pop3(BaseRetriever):
    greeting = "+OK ready"

    @cmd("STAT", state="transaction")
    async def stat(self, session, args):
        msgs = await session.list()
        return f"+OK {len(msgs)} {sum(m.size for m in msgs)}"

    @cmd("RETR", state="transaction")
    async def retr(self, session, args):
        return session.stream("+OK", await session.read(args[0]))   # claimed, dot-stuffed, streamed

    @cmd("DELE", state="transaction")
    async def dele(self, session, args):
        session.mark(args[0])
        return "+OK"

    @cmd("QUIT")
    async def quit(self, session, args):
        await session.commit()                                       # acks the marked, nacks the rest
        return "+OK bye"

An ingestor is the same shape on BaseIngestor, whose session hands the body to submit and maps the engine's per-recipient results to replies.

7

A sender in one screen

A sender implements send(envelope, chunks) and returns a result: delivered, temporary failure (retry with backoff) or permanent failure (bounce). Per-domain limits and retries belong to the host, not the plugin.

8

An authenticator in one screen

from oaken_trunk.plugins.base import BaseAuthenticator

class MyAuthenticator(BaseAuthenticator):
    async def verify(self, request):
        # request is a read-only view: method, path, query, headers, body digest, peer.
        # Return a Principal (key id and surface) or raise AuthError. Never read the body here.
        key = self.keys.get(request.key_id)
        if key is None or not key.verify(request.signature_base, request.signature):
            raise AuthError("bad signature")
        return Principal(key_id=request.key_id, surface=self.surface)
You write You gain
verify(request) A working authenticator (required)
add_key, revoke_key, list_keys Key management through steamer keys
challenge() A protocol-level challenge (SMTP AUTH, for example)

The guard runs it before any route, enforces freshness and replay protection around it, and fails closed on any error. See Security and ADR 0010.

A listener in one screen

from oaken_trunk.plugins.base import BaseListener

class MyListener(BaseListener):
    adds_headers = ["X-My-Check"]          # declared up front; anything else is refused

    async def on_headers(self, event):     # inline and time-bounded; may record a result
        return self.annotate("my-check", "pass")

stored fires after the message is durable and cannot delay acceptance. Mail authentication (DKIM, SPF, DMARC, ARC) will ship as a listener bundle.

10

Testing a plugin

The shared contract suites live in oaken_trunk.testing.contracts (StoreContract, LineServerContract, IngestorContract, RetrieverContract, SenderContract, AuthenticatorContract, ListenerContract). Subclass one, point it at your plugin, and run pytest. The suites cover required behaviour, lease expiry, crash recovery for stores, the streaming and memory rule, and the backpressure replies. Tests never use the network, Docker, Redis or AWS: use fakes (FakeStore, FakeSpool, FakeIngestor, FakeSender) and synthetic fixtures.
