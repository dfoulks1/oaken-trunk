The significant design decisions behind Oaken Trunk, in the order made.

Decisions

An architecture decision record (ADR) captures one significant decision, why it was made, and what follows from it. Records are never rewritten; a later record supersedes an earlier one.

# Decision Status Date
0001 Record architecture decisions accepted 2026-10-24
0002 Trunk is a standalone gateway; Oaken Mail is one consumer accepted 2026-10-24
0003 Messages are never held whole in memory; the default spool is on disk accepted 2026-10-24
0004 At-least-once delivery with lease and ack accepted 2026-10-24
0005 Process model: supervised worker processes, each an event loop plus a small thread pool accepted 2026-10-24
0006 Plugins extend standard base classes accepted, amended by ADR 0014 (stores and line servers) 2026-10-24
0007 The management UI is a separate client on its own port accepted 2026-10-24
0008 The MCP door is generated from the whole registry and gated by caller class accepted 2026-10-24
0009 The API exposes every operation; the CLI and MCP are doors onto it accepted 2026-10-24
0010 Every network surface refuses unsigned requests; the scheme is a plugin accepted 2026-10-24
0011 DKIM and DMARC are native; SPF and ARC where the client is known accepted 2026-10-24
0012 Logs carry no content and are not a product surface accepted 2026-10-24
0013 Retrieval is protocol-agnostic: clients read through operations or a retriever plugin proposed 2026-10-28
0014 Base classes do the work: stores and line servers proposed 2026-10-28
0015 Mail is encrypted at rest, in core, above every store proposed 2026-10-28
