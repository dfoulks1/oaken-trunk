Roadmap

The why and the open questions for what comes next. Nothing here is a promise or a date.

What is built is in CHANGELOG.md; which numbered build prompts are done or open is tracked in CONTRIBUTING.md. This page is the why and the open questions. Nothing here is a promise or a date.

1

Next

  • Contracts and the directory spool (prompts 02-03). Ingestor, Spool and Sender contracts, and a Maildir-style spool: write to tmp/, fsync, atomic rename into new/, lease by rename. batched durability (group commit, one fsync per batch) is in 0.1.
  • HTTP and CLI ingest (05-06). /v1/send as submission into the spool; oaken-trunk submit on stdin.
  • LMTP (07). The clean way to sit behind Postfix; a pipe target covers qmail.
  • Consumer API (08). Lease, fetch, ack, nack over HTTP, plus CLI parity.
2

Later

  • MCP door (17). Generated from the whole registry, gated by caller class: statistics by default, a confirm gate for changes, never message data, off by default. It may share the management UI's listener on its own path, authenticated and local-only by default.

  • Management UI (16). A separate web app on its own port for queue, spool, leases and failures, built only on operations the CLI already has.

  • SMTP ingest with STARTTLS, AUTH and a recipient allowlist.

  • Outbound (send): a Sender plugin kind, queue semantics, bounces. Open: DSN format and retry policy.

  • Redis stream and S3 + SQS spools, with their native consumer-group and visibility-timeout semantics mapped to lease/ack.

  • Write-behind tmpfs over a disk journal. Open: recovery rules.

  • mTLS for consumers.

3

Not planned

IMAP or POP3, mailbox search, spam filtering, and a RAM-resident spool driver.
